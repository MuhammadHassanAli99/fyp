\section{Abstract (200--300 words)}

AURELIA is a cross--platform marketplace application focused on gold commerce.
Buyers and sellers can browse, buy, sell, and auction gold--related listings
(bars, coins, jewellery, and investment gold) through a Flutter client backed by
a Node.js modular--monolith API.

The platform problem addressed by the implemented system is fragmented,
low--trust digital gold trading: users need authenticated accounts, verified
sellers or stores, structured gold attributes (purity/karat, weight units,
making charges, hallmarks, certificates), searchable listings, and communication
channels before completing a trade. AURELIA centralizes these concerns in one
product surface branded as a Gold Marketplace.

Technically, the backend is an Express~5 + TypeScript modular monolith using
MySQL for persistence, Redis for caching (with in--memory fallback), JWT--based
authentication, Zod validation, and Socket.io for realtime chat/presence/auction
rooms. Marketplace domains plug in through a registry interface; the active
marketplace module in the current codebase is \texttt{gold}. Shared platform
modules already present include authentication (including OTP, MFA, OAuth,
passkeys, and device security), KYC/verification, catalog and listings,
auctions, search/filters/maps, favorites and comparison, chat and calls,
notifications, subscriptions and payments, reviews, advertisements, AI
assistance endpoints, moderation, and risk/fraud--related services.

Gold--specific capabilities in code include store applications, purity/rate
quoting, rate history and forecast endpoints, authenticity/assessment helpers,
buy/delivery confirmation flows, bidding, certificates/hallmarks, and
verification requests. The Flutter client exposes corresponding product flows
for auth, listings, search, maps, chat, payments, seller tools, and gold stores.

Expected outcomes of the project are a working end--to--end gold marketplace
client and API with the modules listed above. Property and Vehicles marketplace
schemas exist historically and are currently deactivated in the database; they
are out of active API scope unless later restored.

\section{Problem Significance \& Context}

\subsection{Background \& Motivation}

Gold is traded as bars, coins, jewellery, and investment metal. Digital
listing, pricing (rate per gram/tola/ounce, making charges, wastage),
hallmarking/certificates, and buyer--seller communication are all required for
a usable marketplace. The AURELIA product surfaces these needs under a single
app tagline: ``Buy, sell and auction gold with confidence.''

Stakeholders reflected in the system design include:
\begin{itemize}[leftmargin=1.4em]
  \item End users (guests and registered buyers/sellers)
  \item Gold stores / businesses applying through store workflows
  \item Platform operators via admin, moderation, support, and analytics modules
\end{itemize}

\subsection{Problem Statement}

Buyers and sellers lack a unified, trust--oriented digital channel to list,
price, verify, search, communicate about, and auction gold items with
marketplace--specific attributes (purity, weight, hallmarks, certificates, and
live/quoted rates).

\subsection{Scope \& Assumptions}

\textbf{In scope (confirmed in current codebase):}
\begin{itemize}[leftmargin=1.4em]
  \item Flutter client branded AURELIA (Gold Marketplace)
  \item Modular--monolith API with active \texttt{gold} marketplace module
  \item Platform capabilities: auth/security, KYC/verification, listings,
        auctions, search/filters/maps, favorites/compare, chat/calls,
        notifications, subscriptions/payments, reviews, ads, AI endpoints,
        moderation/risk, seller/support/admin
  \item Gold features: stores, catalog/brands/hallmark authorities, rates and
        quotes, purity standards, authenticity/assessment helpers,
        buy/delivery, auctions/bids, certificates, verification requests
\end{itemize}

\textbf{Out of scope / inactive today:}
\begin{itemize}[leftmargin=1.4em]
  \item Property and Vehicles marketplace API modules (schema/seed rows exist;
        deactivated; no active backend marketplace packages)
\end{itemize}

\textbf{Assumptions / constraints visible in implementation:}
\begin{itemize}[leftmargin=1.4em]
  \item Default AI provider is heuristic/offline; an OpenAI--compatible driver
        is optional via configuration
  \item Payment gateways without configured drivers fall back to manual
        settlement paths
  \item Gold authenticity helpers in code are not chemical assays
\end{itemize}
